# GLB : inventaire borné des ressources — 31 octobre 2026

Base vérifiée : `76633b0f78ce8dd2f7558687e3d01aceb436f2ac`.

L'inspection lit les chunks et les déclarations core de buffers, bufferViews
et images d'un GLB complet de 1 MiB au plus. Les preuves relient les ressources
à leurs pointeurs JSON et, pour les données BIN liées, à leurs plages exactes.
Le catalogue et le journal acceptent l'identité `asset-glb-inspection/1`.
Le profil entre dans le hash d'entrée ; une modification du binaire invalide
l'application d'une ancienne acceptation au nouveau rapport. Les snapshots
conservent les rapports, et le journal séparé conserve les décisions.

La suite locale complète passe : **3 574 tests et 34 sous-tests** sous Python
3.12.14, avec un avertissement de dépréciation du plugin anyio. Les **88 nouveaux
tests** comprennent 78 cas du lecteur et 10 cas d'intégration : bornes, refus
atomique, indices stricts, padding BIN, absence d'accès aux URI, hash, catalogue,
journal et commandes réelles. L'API d'en-tête `probe_media` et les identités
des formats existants restent couvertes par la suite.

La contre-revue indépendante du lecteur n'a trouvé aucun défaut reproductible
dans ce périmètre. Elle a vérifié notamment l'atomicité, les types des indices,
les plages BIN/images, les cardinalités maximales et l'absence d'accès ou de
décodage des URI. La relecture documentaire a précisé le stockage séparé des
décisions et le refus des nombres JSON flottants dans les champs entiers.

La [démonstration conservée](ASSET_GLB_DEMO_2026-10-31.json) utilise uniquement
une fixture fabriquée : triangle, PNG, buffer externe et URI de données déclarés.
Elle retrouve le tag externe proposé, puis accepté après revue ; changer le
binaire retire cette acceptation du nouveau rapport. Aucune coordonnée GPS
n'est inférée. Le résultat enregistré correspond exactement à une réexécution.

Limites : aucun URI n'est ouvert, normalisé ou décodé ; une référence externe
n'établit pas un fichier manquant. Une plage présente ne prouve pas un contenu
décodable. Les extensions ne sont pas parcourues, les autres chunks sont
seulement bornés, et les comptes d'objets sont des déclarations. Un BIN orphelin
ne produit aucun tag de buffer disponible. Les espaces JSON sont acceptés sans
certifier un padding exclusivement `0x20`. Le statut reste `partial` : aucune
validation complète glTF, qualité de modèle, mesure de gain ou capacité de rendu
n'est revendiquée.
